# Flowise vs LangGraph: what each does best, and the hybrid

The SCInsight chat bot, SC Agent Manager and 7 specialists were built twice, as Flowise flows and as LangGraph graphs, on the same
SCInsight API, prompts and model (Qwen 2.5 7B). Both were then given the same 40 role questions plus 3 guard tests.
Per-question detail: [FLOWISE_VS_LANGGRAPH_RESULTS.md](FLOWISE_VS_LANGGRAPH_RESULTS.md) · how to run: [LANGGRAPH_MIRROR.md](LANGGRAPH_MIRROR.md).

## Measured result (2026-10-22, this machine)

| | Flowise | LangGraph |
|---|---|---|
| Right specialist chosen | 41/43 | 41/43 |
| Facts correct (checked on the cited calculation) | 42/43 | 42/43 |
| Errors | 0 | 0 |
| Paused for human approval | 27 | 27 |
| Median time per question | 9.9 s | 9.6 s |
| Approval cycle (pause → manager approves in API → resume → verified decision) | ✓ | ✓ |

**The answers are equivalent.** Both runtimes made the same two routing choices:
- *"How much vitamin C serum base SER-BASE-VC is usable at FAC-1?"* went to Factory Planning instead of Quality.
- *"Is SPF50 going to run out in Warehouse B?"* went to Inventory instead of Warehouse; the answer was still correct.

Those choices come from the shared classifier prompt and the 7B model, not from the runtime. Speed is the same within noise: the
model dominates the time. Accuracy and speed therefore don't decide between the two runtimes. Engineering qualities do.

The first run also exposed a shared weakness: Qwen 7B sometimes returned `{}` instead of the codes written in the question. It was
fixed the same way in both runtimes, with code detecting identifiers before the model, and verified identical in JavaScript and Python
on all 40 questions.

## What each tool does best (from building and running both)

| Concern | Flowise | LangGraph |
|---|---|---|
| Seeing the workflow | **Best**: visual canvas with numbered steps and notes; business users can follow it | Studio shows the graph and each step's state, but you need the code to change it |
| Changing a prompt or a step quickly | **Best**: edit in the UI, save, live | Edit code, rebuild, redeploy |
| Chat front end, conversation starters, embed widget | **Best**: built in | You build it, or use Studio / the API |
| Version control and code review | JSON exports (generated by `build-scinsight.cjs`), hard to review by hand | **Best**: plain Python, normal diffs and reviews |
| Unit tests | Only end to end, through the prediction API | **Best**: in-process tests with a scripted model and the real API (`test_langgraph_mirror.py`, under 2 s) |
| Logic and data handling | JavaScript strings inside nodes; state values must be flat strings; template fallbacks | **Best**: typed state, ordinary functions, subgraphs |
| Human-in-the-loop | Human Input node, resume via `humanInput`; resume answered in 0.2 s | `interrupt()` / `Command(resume)`; resume in 3.0 s here (in-memory dev server); durable checkpoints |
| Gotchas hit while building | `llmUserMessage` ignored without memory, HTTP node throws on non-2xx, `{{ output.x }}` keeps the template text on null | None of these; the same logic was simpler to express |
| Operations | One container, a UI, API keys per flow | LangGraph server (dev mode here); production needs its persistent server |

## Recommended hybrid

```
Flowise  ── chat front door (guardrail, memory, conversation starters, embed)      ← business-facing, editable without code
   └─► LangGraph  scinsight_supervisor + 7 specialist subgraphs                     ← the agent logic: tested, versioned, reviewed
          └─► SCInsight API (data, calculations, approvals, audit)                    ← unchanged: the single governed source of truth
```

1. **Flowise owns the conversation.** The chat bot stays in Flowise; its *Ask the SC Agent Manager* tool calls the LangGraph
   supervisor instead of the Flowise supervisor (one URL change). Conversation starters, embed and prompt tweaks stay no-code.
2. **LangGraph owns the agent logic.** Supervisor, specialists, approval interrupts and the number check live in Python, with unit
   tests and code review. This is where changes are riskiest, so it should be the most testable layer.
3. **Keep the Flowise agentflows as a living diagram** for demos and business review, generated from the same definitions, or retire
   them once the team is comfortable with Studio.
4. **The SCInsight API stays the only authority** for data, calculations and approvals in either runtime, which is why both scored
   identically.

Before production:
- move the LangGraph server from `langgraph dev` (in-memory) to a persistent deployment with PostgreSQL checkpoints
- add tracing for both runtimes (Langfuse)
- re-run `scripts/scinsight_compare.py` after every prompt or model change
